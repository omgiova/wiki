## web_search/web_extract quebrados = plugins web ausentes em plugins.enabled — 11:06
Os tools nativos falham com "no registered web search provider" quando os plugins web não estão listados em `plugins.enabled` no config.yaml (são opt-in). Fix autorizado: `hermes plugins enable web/firecrawl` (+ ddgs, brave_free, exa, parallel, tavily, keenable, searxng, xai). Não edite config.yaml na mão — o agente bloqueia (arquivo sensível); use `hermes plugins enable` / `hermes config set`.

## Testar internals do Hermes com a venv certa — 11:06
Ao testar imports/registry num shell avulso, use `/root/.hermes/venv/bin/python`, NÃO `/usr/bin/python3.12` do sistema. httpx já está na venv; testar com o python do sistema dá falso "ModuleNotFoundError: No module named 'httpx'" e leva a causa raiz errada.

## browser-use local (free): instalação e resolução de PATH — 11:06
Modo local é gratuito (sem conta). Instale `uvx browser-use`; o Hermes resolve o binário `browser-use` do PATH (prepended com `~/.hermes/bin`, venv bin, `~/.local/bin`). Crie shim em `~/.local/bin/browser-use` → `uvx browser-use "$@"`. Local mode: `hermes config set browser.cloud_provider browser-use`. O harness conecta no Chromium via `BU_CDP_URL=http://127.0.0.1:9222`.

## Mudanças de plugin/config só valem na próxima sessão — 11:06
`hermes plugins enable` / `hermes config set` imprimem "Takes effect on next session". O agente vivo carrega o registry no startup; mudanças na sessão atual não refletem no `browser_exec`/web tools da sessão viva até reiniciar o Hermes (gateway/processo). Para validar, teste num subprocesso com a venv ou peça restart.
