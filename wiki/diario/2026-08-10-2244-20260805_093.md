## Guard do Hermes crasha com "embedded null byte" ao executar binários — 14:50
O lifecycle_guard do terminal tenta ler qualquer executável como script; binários ELF (ex: `./cli-proxy-api`, `venv/bin/python`) quebram com `ValueError: embedded null byte`. Não é permissão nem travamento — é bug do guard. Contornar: usar `execute_code` para Python, ou deixar os arquivos prontos e passar o comando pro usuário rodar no terminal da VPS. Não insistir rodando o binário pelo terminal tool.

## `hermes config set` NÃO faz parse de JSON — grava listas como string — 15:40
`hermes config set custom_providers '[{...}]'` grava a lista como string YAML literal (quebra o config). Caminho oficial: `hermes config set custom_providers.0.<campo> <valor>` (índice numérico) para campos pontuais, ou a função interna `_save_custom_provider(base_url=..., name=..., api_mode=...)` (em `hermes_cli/main.py`) via `venv/bin/python -c` — ela gerencia a lista e deduplica por URL. Útil para registrar qualquer provider custom (OpenAI-compatible, Anthropic-compatible) no Hermes.

## CLIProxyAPI é sistema novo na VPS (systemd) — 16:00
Instalado em `/opt/cliproxyapi` (binário `cli-proxy-api` v7.2.123, release oficial), serviço `systemd`: `cliproxyapi` (status/restart/stop; logs via `journalctl -u cliproxyapi -f`). Pitfall: **systemd não define $HOME** → o service precisa de `Environment=HOME=/root` senão morre com "resolve auth dir: $HOME is not defined". Config em `/opt/cliproxyapi/config.yaml` (api-keys reais trocadas — chave de exemplo desabilita endpoints), auth OAuth em `/root/.cli-proxy-api/` (arquivo `claude-<email>.json`). API: `http://localhost:8317`, modo anthropic_messages; provider custom `cliproxy` registrado no Hermes (`CLIPROXY_API_KEY` no `.env`). Login OAuth pelo celular exige túnel SSH `ssh -L 54545:localhost:54545 root@IP_VPS` — o redirect vai pra `localhost:54545` que precisa chegar na VPS.
